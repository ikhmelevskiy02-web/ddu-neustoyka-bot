# Калькулятор неустойки по ДДУ — Telegram-бот

Бот считает неустойку за просрочку передачи объекта по договору участия в
долевом строительстве (214-ФЗ), а также госпошлину и штраф 5%. Полная
правовая база расчёта — в [`docs/LEGAL_SPEC.md`](docs/LEGAL_SPEC.md), её
обязательно нужно прочитать перед изменением логики в `src/domain/`.

## Архитектура

```
src/
├── main.py              # точка входа, сборка бота
├── config.py             # переменные окружения
├── domain/                # ЧИСТАЯ бизнес-логика, без Telegram и без LLM
│   ├── models.py
│   ├── rates.py           # таблица ключевой ставки ЦБ РФ
│   ├── moratorium.py       # логика исключения периода моратория
│   ├── calculator.py       # расчёт неустойки (ч. 2 ст. 6 214-ФЗ)
│   ├── gosposhlina.py       # расчёт госпошлины (ст. 333.19, 333.36 НК РФ)
│   └── shtraf.py             # расчёт штрафа 5% (ч. 3 ст. 10 214-ФЗ)
├── llm/                   # интеграция с Groq — ТОЛЬКО текст, не арифметика
│   ├── groq_client.py
│   ├── extraction.py       # извлечение параметров из свободного текста
│   └── explain.py            # дружелюбный пересказ уже посчитанного результата
├── bot/                   # aiogram: диалоги, клавиатуры, форматирование
│   ├── states.py
│   ├── keyboards.py
│   ├── formatting.py
│   ├── utils.py             # парсинг дат/сумм, введённых вручную
│   └── handlers/
│       ├── start.py
│       ├── common.py         # /cancel + глобальный обработчик ошибок
│       └── calculator.py
└── data/
    └── key_rates.json     # таблица ключевой ставки ЦБ РФ (нужно обновлять!)

scripts/
└── update_key_rate.py    # безопасный CLI для обновления key_rates.json

.github/workflows/tests.yml  # CI: pytest на 3.11 и 3.12 при каждом push/PR
```

**Важный принцип:** Groq никогда не считает деньги и не работает с датами
напрямую — он только извлекает параметры из текста пользователя и оформляет
готовый результат. Вся арифметика — в `domain/`, покрыта тестами и не зависит
от LLM. Если `GROQ_API_KEY` не задан, бот продолжает работать в пошаговом
режиме (вопрос-ответ через кнопки), просто без распознавания свободного текста.

## Быстрый старт (локально)

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt

cp .env.example .env
# Впишите в .env:
#   BOT_TOKEN     — токен от @BotFather
#   GROQ_API_KEY  — ключ с https://console.groq.com (опционально)

export PYTHONPATH=src              # Windows (PowerShell): $env:PYTHONPATH="src"
python src/main.py
```

## Тесты

Вся бизнес-логика (расчёт неустойки, госпошлины, штрафа, работа с мораторием)
покрыта тестами и **проверена на реальном примере** — данных из фактического
судебного искового заявления, приложенного при разработке проекта:

```bash
pip install -r requirements-dev.txt
pytest -v
```

Все тесты должны быть зелёными перед любым деплоем — они гарантируют, что
рефакторинг не изменил сумму неустойки незаметно для человека.

## Что нужно поддерживать в актуальном состоянии

1. **`src/data/key_rates.json`** — таблица ключевой ставки ЦБ РФ. Обновляйте
   через `python scripts/update_key_rate.py add --date YYYY-MM-DD --rate X.XX`
   после каждого заседания Совета директоров ЦБ РФ
   (график: https://cbr.ru/dkp/cal_mp/, данные для сверки:
   https://www.cbr.ru/hd_base/keyrate/). Скрипт сам проверяет формат даты и
   разумность значения ставки, но не ходит в интернет сам — вносить значение
   должен человек, сверившись с официальным источником (это осознанное решение:
   для юридически значимого расчёта неверно спарсенное значение опаснее, чем
   отсутствие автообновления). Даты в таблице — это даты **вступления в силу**
   (обычно понедельник после пятничного заседания), см. комментарий в файле.
2. **`docs/LEGAL_SPEC.md`** — следить за новой практикой КС РФ/ВС РФ по
   214-ФЗ и за изменениями Постановления Правительства РФ № 326 (следующая
   ключевая дата — конец 2026 года, когда истекает текущая отсрочка выплаты
   уже предъявленных требований).
3. **Модель Groq** (`GROQ_MODEL` в `.env`) — Groq периодически снимает модели
   с поддержки (см. https://console.groq.com/docs/deprecations). На август
   2026 года `llama-3.3-70b-versatile` и `llama-3.1-8b-instant` уже
   деприкейчены, используется `openai/gpt-oss-120b`.

## CI

При каждом push/PR в `.github/workflows/tests.yml` автоматически прогоняются
все тесты на Python 3.11 и 3.12 — merge без зелёного статуса не рекомендуется,
т.к. это единственная защита от незаметного изменения суммы неустойки при
рефакторинге.

## Деплой в прод

`Dockerfile` уже готов к сборке:

```bash
docker build -t ddu-neustoyka-bot .
docker run -d --env-file .env --name ddu-bot ddu-neustoyka-bot
```

Для реального прода дополнительно стоит рассмотреть (пока не реализовано):
- переход с `MemoryStorage` на Redis для FSM (чтобы состояние диалога не
  терялось при перезапуске и работало при нескольких инстансах);
- вебхуки вместо long polling;
- логирование/мониторинг ошибок (Sentry и т.п.) поверх уже добавленного
  общего обработчика необработанных исключений (`bot/handlers/common.py`).

## Дисклеймер

Бот даёт справочный расчёт, а не юридическую консультацию и не гарантирует
решение суда — это прямо указано в ответах бота и должно оставаться на месте
при любых изменениях текстов.
